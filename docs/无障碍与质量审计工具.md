# 无障碍（axe）与网页质量（Lighthouse）审计工具

> 2026-11-19 安装。两份工具都是开源免费：axe-core（Deque，MPL-2.0）、Lighthouse（Google，Apache-2.0）。
> 对应"剩余工作优先级"里原计划的"优先级 2"那批测试。
>
> 完整测试分层与 Playwright 覆盖矩阵见 [Playwright测试矩阵与执行手册.md](./Playwright测试矩阵与执行手册.md)。

## 一、这两个工具是做什么的

### axe（@axe-core/playwright）

**无障碍（accessibility / a11y）测试**引擎。自动扫描真实渲染的 DOM，按 WCAG 2.0/2.1 的 A/AA 规则找出阻碍残障用户使用的问题：

- 文字与背景对比度不足（弱视用户看不清）
- 表单控件没有可访问名称（读屏软件念不出"这是什么"）
- 按钮的可见文字与 aria-label 不匹配
- 滚动区键盘不可达（只用键盘的用户滚不动提词）
- 图片缺 alt、语义结构缺失等

对本项目的价值：Telegram WebView 里字小、对比度低、控件点不到/读不出是常见投诉，axe 能在发布前揪出来。

### Lighthouse（Google）

**网页质量综合审计**。对页面跑一次，给出五项 0–100 评分和优化建议：

| 维度 | 含义 |
|---|---|
| Performance | 加载/交互速度（FCP、LCP、TBT、CLS 等核心指标） |
| Accessibility | 无障碍，与 axe 部分重叠但评分口径不同 |
| Best Practices | 控制台报错、HTTPS、弃用 API 等 |
| SEO | meta 描述、robots、语义标签等 |
| PWA | 已并入其他项（Lighthouse 13 移除了独立 PWA 分类） |

## 二、怎么跑

```bash
# axe 无障碍门禁（Chromium + WebKit，约 2.5 分钟）
npm run test:a11y

# Lighthouse 质量审计（本地起临时服务器，约 1 分钟，报告写到 lighthouse-report/）
npm run audit:lighthouse

# 审计线上生产版
node tools/lighthouse-audit.mjs https://teleprompter-49y.pages.dev/
```

- axe 测试在 `e2e/accessibility.spec.mjs`，被 `npm run test:e2e` / `test:e2e:all` 自动包含（多 3 项）。
- Lighthouse 报告目录 `lighthouse-report/` 已加入 `.gitignore`（可随时重跑生成，不进仓库）。

## 三、axe 门禁策略（2026-11-19 已升级为零违规硬门禁）

首审时为了不让历史欠账永远红灯，先把 13 处 serious/critical 违规记为**基线** `e2e/a11y-baseline.json`：只在「新类别出现」或「节点数增加」时失败，修好了下降不报警。基线经 Chromium + WebKit 双引擎验证一致（axe 读 CSS 计算值）。

当日清单全部修复后，基线已清零（`main: {}` / `settings: {}`）。现在**任何 serious/critical 违规都会被判为新增并让测试失败**，从「只防退化」升级为「零违规硬门禁」。

## 四、首次审计发现的问题清单（均已修复）

### axe（真实问题，按严重度排序）

| 规则 | 级别 | 涉及元素 | 原因 | 修复 |
|---|---|---|---|---|
| `color-contrast` | serious | 副标题、Speed 标签、各 hint、设置项标签（主界面 2 处 / 设置 11 处） | 灰色 `#79808c` 在白底上对比度仅 **3.97** < 4.5 | `--muted` 改为 `#5f6672`（白底 5.78 / 浅灰底 5.35） |
| `label` | critical | `#speedBar`、`#setFontSize`、`#setMirror`、`#setReadMark`、`#setSpeed`、`#setFinishCard` | 6 个表单控件无可访问名称 | 给已有 `<label>` 加 `for` 关联；完成卡开关的 `<span>` 改成 `<label for>`。`for` 方案的名称随七语 i18n 自动切换，无需新增翻译键 |
| `select-name` | critical | `#setAlign`、`#setReadMarkStrength` | 两个下拉框无标签 | 同上，`<label for>` 关联 |
| `label-content-name-mismatch` | serious | `#btnFontDown`、`#btnFontUp` | 可见文字 A−/A+ 不在 aria-label 里 | aria-label 改为「A− 缩小字号」「A+ 放大字号」 |
| `scrollable-region-focusable` | serious | `#viewport` | 提词滚动区键盘不可达 | 加 `tabindex="0"`，纯键盘用户可用方向键滚动 |
| `landmark-one-main`（Lighthouse） | 最佳实践 | 页面整体 | 缺 `<main>` 地标（axe 的 wcag 标签集不覆盖） | `#viewport` 由 `<div>` 改为 `<main>`，CSS 用 id 选择器故布局不变 |

修复方式遵循「不碰核心逻辑」：改动集中在 1 个 CSS 变量 + 8 个 `<label for>` + 2 个 aria-label + 1 个标签名/属性。

### Lighthouse 本地评分（390×844 移动端模拟）

| 维度 | 首审 | 修复后 |
|---|---|---|
| Performance | 77 | 77 |
| Accessibility | 88 | **100** |
| Best Practices | 96 | 96 |
| SEO | 82 | 82 |

Accessibility 满分来自对比度、控件名称、`<main>` 地标全部补齐。仍低的分项属另一类欠账：FCP/LCP 3.3s、Speed Index 约 32s、未压缩/未使用的 CSS/JS、缺 meta description——这些是性能与 SEO 范畴，不在本轮无障碍修复范围。

**注意两个"假象"**（本地审计脚本的产物，不是产品真实问题）：
- `robots.txt is not valid`：临时测试服务器对 `/robots.txt` 也返回了 index.html 的 HTML 内容，所以解析报错。线上 Cloudflare Pages 无此问题。
- `errors-in-console`：同理，favicon 等请求拿到了 HTML 导致的解析错误。真实线上需在浏览器控制台确认。
