# 无障碍（axe）与网页质量（Lighthouse）审计工具

> 2026-11-19 安装。两份工具都是开源免费：axe-core（Deque，MPL-2.0）、Lighthouse（Google，Apache-2.0）。
> 对应"剩余工作优先级"里原计划的"优先级 2"那批测试。

## 一、这两个工具是做什么的

### axe（@axe-core/playwright）

**无障碍（accessibility / a11y）测试**引擎。自动扫描真实渲染的 DOM，按 WCAG 2.0/2.1 的 A/AA 规则找出阻碍残障用户使用的问题：

- 文字与背景对比度不足（弱视用户看不清）
- 表单控件没有可访问名称（读屏软件念不出"这是什么"）
- 按钮的可见文字与 aria-label 不匹配
- 滚动区键盘不可达（只用键盘的用户滚不动提词）
- 图片缺 alt、语义结构缺失等

对本项目的价值：Telegram WebView 里字小、对比度低、控件点不到/读不出是常见投诉，axe 能在发布前揪出来。

### Lighthouse（Google）

**网页质量综合审计**。对页面跑一次，给出五项 0–100 评分和优化建议：

| 维度 | 含义 |
|---|---|
| Performance | 加载/交互速度（FCP、LCP、TBT、CLS 等核心指标） |
| Accessibility | 无障碍，与 axe 部分重叠但评分口径不同 |
| Best Practices | 控制台报错、HTTPS、弃用 API 等 |
| SEO | meta 描述、robots、语义标签等 |
| PWA | 已并入其他项（Lighthouse 13 移除了独立 PWA 分类） |

## 二、怎么跑

```bash
# axe 无障碍门禁（Chromium + WebKit，约 2.5 分钟）
npm run test:a11y

# Lighthouse 质量审计（本地起临时服务器，约 1 分钟，报告写到 lighthouse-report/）
npm run audit:lighthouse

# 审计线上生产版
node tools/lighthouse-audit.mjs https://teleprompter-49y.pages.dev/
```

- axe 测试在 `e2e/accessibility.spec.mjs`，被 `npm run test:e2e` / `test:e2e:all` 自动包含（多 3 项）。
- Lighthouse 报告目录 `lighthouse-report/` 已加入 `.gitignore`（可随时重跑生成，不进仓库）。

## 三、axe 基线门禁策略

首次审计发现的问题没有立刻当成失败（否则会永远红灯挡住每次 push），而是记为**基线** `e2e/a11y-baseline.json`：

- 只有当「出现新的违规类别」或「某类违规节点数增加」时才失败；
- 修好了、违规数下降，不会让测试失败；
- 基线经 Chromium + WebKit 双引擎验证，axe 读 CSS 计算值，两者结果一致。

这样既持续盯住无障碍退化，又不因历史欠账阻塞发布。等下面清单的问题修完，可把基线清零、升级为硬门禁。

## 四、首次审计发现的问题清单

### axe（真实问题，按严重度排序）

| 规则 | 级别 | 涉及元素 | 说明 |
|---|---|---|---|
| `color-contrast` | serious | 副标题、Speed 标签、各 hint、设置项标签（主界面 2 处 / 设置 11 处） | 灰色 `#79808c` 在白底上对比度仅 **3.97**，WCAG AA 要求 **4.5**。把灰色调深即可。 |
| `label` | critical | `#speedBar`、`#setFontSize`、`#setMirror`、`#setReadMark`、`#setSpeed`、`#setFinishCard` | 6 个表单控件无可访问名称。给每个 input 加 `aria-label` 或用 `<label for>` 关联。 |
| `select-name` | critical | `#setAlign`、`#setReadMarkStrength` | 两个下拉框无标签，同上处理。 |
| `label-content-name-mismatch` | serious | `#btnFontDown`、`#btnFontUp` | 按钮可见文字是 A−/A+，但 aria-label 是 "font size down/up"，可见文字不在可访问名称里。 |
| `scrollable-region-focusable` | serious | `#viewport` | 提词滚动区键盘不可达，加 `tabindex="0"`。 |

另有 Lighthouse 单独报的 `landmark-one-main`：页面缺 `<main>` 地标（axe 的 wcag 标签集未覆盖此最佳实践）。

### Lighthouse 本地评分（390×844 移动端模拟）

| 维度 | 分数 |
|---|---|
| Performance | 77 |
| Accessibility | 88 |
| Best Practices | 96 |
| SEO | 82 |

低分项：FCP/LCP 3.3s、Speed Index 31.9s、未压缩的 CSS/JS、未使用的 CSS/JS、缺 meta description。

**注意两个"假象"**（本地审计脚本的产物，不是产品真实问题）：
- `robots.txt is not valid`：临时测试服务器对 `/robots.txt` 也返回了 index.html 的 HTML 内容，所以解析报错。线上 Cloudflare Pages 无此问题。
- `errors-in-console`：同理，favicon 等请求拿到了 HTML 导致的解析错误。真实线上需在浏览器控制台确认。

## 五、修复优先级建议

若要消除无障碍欠账，按此顺序（改动集中在 CSS 变量 + input 的 aria-label，不碰核心逻辑）：

1. 调深灰色文字色值（一处 CSS 变量，一次消掉 13 处 color-contrast）；
2. 给 6 个表单控件 + 2 个 select 加 `aria-label`；
3. 给 `#viewport` 加 `tabindex="0"`；
4. 修正 A−/A+ 按钮的 aria-label 使其包含可见文字；
5. 给页面加一个 `<main>` 地标。

全部修完后，把 `e2e/a11y-baseline.json` 的计数清零，让 axe 从"基线门禁"升级为"零违规硬门禁"。
